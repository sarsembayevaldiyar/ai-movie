# DECISIONS.md: решения арт-директора и технического директора

Формат: решение → почему. Всё, где брендбук молчит или условия задачи противоречат окружению.

## Процесс
1. **Без промежуточных остановок.** Пользователь попросил «полностью делай сам». Остановка после шага 2 пропущена, раскадровка утверждена мной как арт-директором.
2. **Установленные skills:** группа A + пункты 8–10 из `docs/SKILLS_REPORT.md`. Список и правила — в `CLAUDE.md`.

## Бренд
3. **Цвета и геометрия градиентов и линий** взяты из векторных объектов PDF (стопы 0 / 0,638 / 1; линии ≈ 1,96 px @1080p), а не на глаз. Подробно — в `docs/BRAND.md`.
4. **Шрифт — только Inter** (Semibold для заголовков, Regular для текста, Medium для слогана). Gilroy в брендбуке нужен только для лого региональных хабов, поэтому в видео он не нужен. Inter — OFL, файлы лежат локально в `public/fonts`.
5. **Логотип в финале — инверсная основная версия на чёрном** (`logos/4.webp`). Брендбук разрешает её «в особых случаях при разработке имиджевой продукции». Логотип появляется один раз. Его анимация — только прозрачность и появление частей оригинального файла, без перерисовки. Финальный кадр держит логотип 1:1.
6. **Фирменные элементы (текст, логотип, подложки-градиенты) — в DOM-слое поверх WebGL**, вне тонмаппинга: их HEX на выходе совпадают с брендбуком. Эмиссивные 3D-элементы в фирменном цвете (граница, сеть, орбиты) подаются в шейдер с обратной компенсацией ACES, поэтому их ядро после тонмаппинга попадает в фирменный HEX.
7. **Зелёная «матричная» стилистика презентаций не используется:** её нет в брендбуке, а брендбук — закон. Из презентаций берём только факты.
8. **Фирменная рифма фильма:** градиент бренда = свечение атмосферы по лимбу, фирменные линии = орбиты. Финальный кадр повторяет композицию обложки брендбука.

## Контент
9. **Шесть тезисов** (T1–T6) выбраны из цифр, которые совпадают в RU- и EN-версиях презентации. Инвестиции ($1B+ / $940M+) исключены из-за расхождения. Цитата Президента и логотипы партнёров не используются.
10. **Язык — русский.** Слоган «Join the unicorn game» остаётся на английском: так он записан в брендбуке (стр. 17–18) и презентациях.
11. **Пало-Альто** отсутствует в Natural Earth populated places, поэтому дуга ведёт в ближайший город из набора, San Jose (~25 км). На экране точки не подписаны.

## Техника
12. **3D-хост — `@remotion/three` `<ThreeCanvas>`**, но кадр рисует собственный HDR-конвейер (`src/gl/FilmPipeline.ts`), а не автоматический рендер R3F. Причины:
    - нужны сабкадры для motion blur (сцена должна вычисляться в дробные моменты времени — это невозможно через React-перерендер);
    - нужны свой bloom, ACES и порядок постобработки.

    `useFrame` не используется (запрет skill `remotion-best-practices`). Состояние мира — чистая функция времени `update(t)`.
13. **Motion blur — накопление сабкадров** в HDR-буфере с затвором 180°. Число сабкадров адаптивное: 1–2 на медленных планах, до 8 на пролёте сквозь облака. `@remotion/motion-blur` не используется: он перерисовал бы и WebGL, и DOM целиком, а это в N раз дороже, и в headless-шелле Chrome 141 нет HTML-in-canvas.
14. **Антиалиасинг:** на SwiftShader MSAA 4× стоит ~250 мс на кадр 1080p, поэтому в финальном рендере вместо него используется суперсэмплинг. Мастер рендерится в 3840×2160, версия 1080p — даунскейл Lanczos из 4K (4 сэмпла на пиксель). Внутри шейдеров аналитический AA: мягкий лимб, спрайты звёзд с гауссовым профилем, линии с smoothstep по ширине.
15. **Без GPU.** WebGL идёт через SwiftShader (`--gl=swangle`), браузер — предустановленный headless-shell Chromium 141. Параллельные вкладки не ускоряют рендер (SwiftShader уже занимает 4 ядра), поэтому `concurrency = 1–2`.
16. **Кадры захватываются в PNG** (без потерь). JPEG 80 по умолчанию дал бы блоки в тёмных градиентах.
17. **Зерно плёнки** — детерминированный хэш от (пиксель, номер кадра) в композит-шейдере и тонкий DOM-слой поверх текста. Плюс TPDF-дизеринг против бандинга в 8 бит.
18. **Вертикальная версия 1080×1920 не делается.** Это опция из ТЗ, а время рендера на CPU ограничено.
